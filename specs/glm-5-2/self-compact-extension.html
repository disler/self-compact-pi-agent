Purpose

Build a standalone pi coding-agent extension that lets a long-running autonomous agent compact itself on its own terms: a self_compact handoff tool, three context-threshold levels (soft / warning / forced) with CLI flags, a context-bar UI, editable prompt files for each interaction, and human-in-the-loop slash commands. The extension lives entirely under apps/glm-5-2/ and depends on no other extension.

Problem

Long-running autonomous agents exhaust their context window. A full window means context rot (degraded reasoning) and wasted spend on state-of-the-art models. Pi's built-in auto-compaction triggers late and summarizes mechanically; there is no way for the agent to voluntarily hand off a "note to self" and resume the exact next action after compaction, and no graduated warning UI before the hard cutoff.

Solution

A single extension, self-compact.ts, plus three editable prompt markdown files under .pi/self-compact/. The extension registers four CLI flags, one handoff tool, three slash commands, a custom footer (context bar), and a session_before_compact hook that replaces pi's default summarization prompt with the user's compaction-message file (or the --compact-prompt override). The handoff tool saves a validated note, locks all other tools, ends the run, compacts once idle, then restores tools and resumes the note verbatim with no human message.

[] Phase 1: Skeleton, flags & thresholds

Create the extension entry, register four string CLI flags, and implement pure threshold parsing/resolution. Thresholds accept whole token counts, k/m suffixes, or %; the hard limit (warning + buffer) is capped at 90% of the context window and invalid specs are rejected. Defaults: soft 225k, warning 250k, buffer 20k (force 270k).

1.1 Entry & flags

  • [] Create extensions/self-compact/self-compact.ts with export default function (pi: ExtensionAPI) and the four pi.registerFlag calls: compact-soft-at ("225k"), compact-at ("250k"), compact-buffer ("20k"), compact-prompt ("").
  • [] Capture pi.getFlag values once at session start (after CLI values are applied) into a resolved config object.

1.2 Pure threshold helpers (thresholds.ts)

  • [] parseTokenSpec(spec: string): {tokens?: number, percent?: number} | null — parse "225k", "20%", "100000", "1m", "0"; reject garbage.
  • [] resolveThresholds(flags, contextWindow): {soft, warning, force, bufferPct} | {error} — convert each spec to tokens (percent × window), compute force = warning + buffer, cap force at 90% of window, reject if soft > warning or warning > force or invalid.
  • [] Return both token counts and percent-of-window for each threshold (used by the bar markers).

1.3 Handoff state (state.ts)

  • [] readHandoff(dir)/writeHandoff(dir, state) for .pi/self-compact/handoff.json holding {note, state, savedTools, cycleCount, error}.
  • [] On session_start, read handoff; if a pending note exists and state is compacting/locked, restore locked tools and re-arm compaction for when the agent goes idle (reload recovery).

[] Phase 2: self_compact handoff tool & tool locking

Register the self_compact tool. It validates the note (non-blank, ≤ 24,000 chars), saves it, locks every other tool, and ends the current run cleanly via terminate: true.

2.1 Tool registration

  • [] pi.registerTool with name:"self_compact", a TypeBox schema {note_to_self: Type.String()}, and promptSnippet/promptGuidelines instructing the agent to write a handoff note then call it.
  • [] execute rejects blank notes (trim empty) with a clear error content block.
  • [] execute rejects notes over 24,000 characters with a clear error content block.

2.2 Save, lock, terminate

  • [] On valid note: snapshot current pi.getActiveTools() into savedTools, persist the note + state:"compacting" via writeHandoff and pi.appendEntry("self-compact-handoff", {note}).
  • [] pi.setActiveTools(["self_compact"]) to lock all other tools until compaction succeeds.
  • [] Return {content:[{type:"text",text:"Note saved. Compacting once idle…"}], terminate:true} to end the run cleanly.

2.3 Threshold-driven locking

  • [] On turn_end, compute usage; if percent ≥ force threshold and state is normal/warning, call setActiveTools(["self_compact"]) and set state:"locked" (other tools blocked).

[] Phase 3: Compaction prompt override & resume

Drive compaction once idle, replace pi's default summarization prompt with the user's file (or --compact-prompt), return the note verbatim after success, restore tools, and preserve the note + lock on failure.

3.1 Trigger compaction when idle

  • [] On turn_end where a pending note exists and ctx.isIdle(), call ctx.compact({ onComplete, onError }).

3.2 Override the summarization prompt (session_before_compact)

  • [] Resolve the override prompt: --compact-prompt value if non-empty, else the contents of USER_PROMPT_COMPACTION_MESSAGE.md.
  • [] When an override exists: serialize messagesToSummarize + turnPrefixMessages via serializeConversation(convertToLlm(...)), build a single user turn that contains the override prompt + the conversation + the pending note labelled "next action to preserve", call ctx.modelRegistry.complete(ctx.model, ...) with cacheRetention:"none" and the event signal, and return {compaction:{summary, firstKeptEntryId, tokensBefore, usage, details:{note}}}.
  • [] If the model is missing or the call fails, return {cancel:true} so compaction aborts and session_compact_failed fires (note preserved, tools stay locked).
  • [] If no override prompt exists at all, return undefined to let pi use its default compaction.

3.3 Resume after success

  • [] On session_compact success: restore pi.setActiveTools(savedTools), set state:"normal", increment cycleCount, clear the persisted note, and call pi.sendUserMessage(note) to return the note verbatim and continue without a human message.

3.4 Preserve on failure

  • [] On session_compact_failed: keep the pending note, keep tools locked (setActiveTools(["self_compact"])), record error, notify the user. Reload recovery (Phase 1.3) re-arms compaction from the saved note.

3.5 Testing Strategy

  • [] pi -e ... --help loads with the hook registered

[] Phase 4: Context-bar footer

Render a 20-cell usage bar (5% each): cached #, uncached =, free -, with visible ~ (soft), ! (warning), | (force) markers overlaid at their cells, followed by the used percent.

4.1 Pure bar renderer (thresholds.ts)

Notes

Key API decisions

  • Flags: pi.registerFlag(name,{type:"string",...}) + pi.getFlag(name). Unknown CLI flags land in Args.unknownFlags keyed by the flag name (e.g. --compact-soft-at 20% → "compact-soft-at"=>"20%"), then override the registered default.
  • Tool blocking: pi.setActiveTools(["self_compact"]) is the lock; restoring pi.setActiveTools(savedTools) unlocks. Snapshot savedTools before locking.
  • End the run: the tool returns terminate:true so pi does not bill another LLM turn after the handoff.
  • Compaction once idle: trigger ctx.compact() from turn_end only when ctx.isIdle() and a note is pending.
  • Override the summary prompt: session_before_compact returning a full CompactionResult replaces pi's default summarization; customInstructions alone would only append, so we generate the summary ourselves (pattern from example-extension-custom-compaction.md).
  • Resume: pi.sendUserMessage(note) returns the note verbatim and starts a continuation turn with no human message.
  • Cached portion: ContextUsage has only tokens; the cached share comes from the last assistant message's usage.cacheRead (read from ctx.sessionManager.getBranch()).
  • Built-in /compact: left alone; it still routes through our session_before_compact override so the configured summary prompt applies.

Risks / tradeoffs

  • Custom summarization needs the active model + API key at compact time. On failure we cancel and keep the note locked so the user can retry via /self-compact-now or a reload.
  • Sending the soft/warning prompts as user messages starts a turn; the state machine sends each at most once per threshold crossing to avoid loops, resetting to normal after a successful compaction.
  • appendEntry("self-compact-handoff", {note}) plus a handoff.json file gives both session-durable and reload-durable recovery.
